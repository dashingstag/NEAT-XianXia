# Runtime contracts

Live viewers request the optional leaderboard with `{"command":"watch_wealth","enabled":true}` and unsubscribe by sending false. Each connection starts unsubscribed. Closed-tab frames omit the field. Subscribed frames include a complete ranking, including when paused, so a dropped frame cannot lose an update. The server reuses the ranking across unchanged ticks and invalidates it on load, reset and mortality edits. Full experiment summaries and offline town fixtures still include the ranking.

## Watched-purchase inspector contract

For the last-item acceptance scenario, expose an optional `last_decision` on the selected person. A missing or null value means no captured decision. Keep the existing `choices` as a preview computed at inspection time. Capture the shop and owner IDs when deciding so a later ownership change cannot rewrite history.

Example for the buyer who reached an empty shelf:

```json
{"decision_tick":120,"actor_id":4,"action":"ShopGoods","shop_id":7,"owner_id":2,"product_id":17,"resolution_tick":124,"outcome":"out_of_stock","quantity":0,"buyer_charge":0,"shop_proceeds":0,"market_levy":0}
```

Before arrival, resolution tick and outcome are null. For the successful buyer, outcome is `purchased`, quantity is one, and the charge equals shop proceeds plus the levy for this meal. Read actual settled amounts from the transaction. Missing history stays distinguishable from an attempt that failed. The most recent settled purchase is also retained in last_purchase while the person stays watched. Other rejected purchase attempts report unavailable. Candidate counts map each action to [admitted, omitted] at the main offer limit, after domain preselection. The top-level counts describe the preview. Counts inside last_decision describe the captured choice. Watch data is excluded from checkpoints.

The server owns the world and accepts a local viewer. The handoff launcher binds each backend to loopback port zero and reads its assigned port and process ID from the child's atomic readiness file. It passes that port to the viewer via XIANXIA_PORT. Reset-capable experiments receive a socket from their owning launcher.

Each wire message has a four-byte little-endian payload length. Commands are UTF-8 JSON. Replies begin with XNC1 and JSON. Snapshot payloads begin with XNS1, followed by little-endian version (u16), flags (u16, bit zero means paused), tick (u64), allocated count (u32), sample count (u32), metadata byte length (u32) and, since version 2, animal record count (u32). JSON metadata, sample records, then animal records follow. Each 16-byte sample contains ID (u32), x/y (f32), and four bytes for action/flags, cargo/flags, health/age flag, and home. Each 16-byte animal record contains ID (u32), x/y (f32), species (u8), action (u8), health (u8, top bit means young) and heading (u8, fraction of 2pi). The viewer rebuilds wildlife.animals from the records; full experiment reports keep the JSON array. Action IDs occupy six bits. Coordinate and ID changes must agree across the encoder, field renderer and picking implementation.

`{"command":"map_layers"}` replies with XNC1 JSON carrying `map_layers`: `map` (the MapSpec), `explored` (`cols`, `rows`, `chunk` size and `known`, one byte per chunk, 1 when any settlement has visited it) and `terrain` (`cols`, `rows`, `cell` size and the base64 byte grids `classes`, `elevation` and `qi`). Grids are row-major from the north-west corner and are sampled at cell centres. Class bytes follow `Terrain`: Water 0, Rock 1, Marsh 2, Forest 3, Fertile 4, Grass 5. Elevation and qi scale 0..1 to 0..255. Send `"terrain":false` to refresh only `explored`. Snapshots never carry these grids.

Current saves use XXSAVE31 to preserve campsite rumours. The XXSAVE30 envelope adds settlement governance and temporary happiness awards to XXSAVE19. XXSAVE19 includes the world, the procedural map specification, exploration state, and outcome-memory payloads. The loader accepts the plain XXSAVE15 world from the 48-sensor rollout, the subsequent XXSAVE15 procedural map payload, and the experimental XXSAVE15 through XXSAVE18 memory envelopes. Legacy 42-sensor genomes migrate to the widened schema while retaining optional memory nodes and their connections. The world publishes its hill center and radius in the snapshot field `hill`. Saves through version 13 restore the historical center (1500, 1380) and radius 360. The included v12 fixture exercises the introduction of relationship state. Saves 1 through 3 predate the supported migration range. For a persistent field, test load, advance, save, reopen and replay. For an optional inspector field, exercise both an older frame and a frame containing the field.
