# Architecture review and parallel development plan

Reviewed 19 November 2026. The native Rust simulation and Godot observatory should be the continuing game. Keep the browser prototypes runnable as small design experiments. Bring proven rules and scenarios across individually. The older Python XianXia checkout is a source of world-building ideas.

## What to preserve

The native world owns time, people, goods, money and outcomes. Rayon can evaluate decisions from an immutable view before the simulation applies them in a defined order. Physical arrival, finite stocks, reservations, wages and ledger checks make actions meaningful. The independent NEAT crate, exact replay tests, old-save readers and headless viewer fixture are assets. Keep those boundaries through the next round of changes.

## Findings in priority order

1. **Protect the running world before assigning agents.** The reviewed workspace has no Git baseline. The generic protocol exercise defaults to the live port and sends reset immediately. Establish a source-only baseline, exclude saves and build caches, and give each worker a checkout, temporary checkpoint and isolated test endpoint. Make the protocol harness start its own backend or require an explicitly isolated one. See `experiments/check_protocol.py`.
2. **Decouple observation from ticking.** While connected, the runner constructs a snapshot every 100 ms, even when paused. Each calls the full world summary, including accounts, leaderboard and optional inspector work. The position sample is bounded but global query work still grows with population. Send a fast movement frame, a versioned map layer, and slower or requested inspector, council and wealth views. Cache by simulation revision and selection, allowing world edits while paused to invalidate the cache. Keep a full report for experiments. Measure snapshot generation, payload and client frame time separately from tick time. See `sim-runner/src/main.rs` and `World::summary`, `snapshot_with_wildlife` in sim-core.
3. **Make action competition visible.** `World::offer` stops admitting candidates after 64 in enumeration order. Later domains can silently lose representation before a brain evaluates them. Measure rejected counts by action family on dense-town fixtures. If saturation is material, bound target search per action family and compare the surviving choices under a documented deterministic rule. Also distinguish a current policy preview from a historical decision. `World::trace` recomputes offers against the current world. Capture decision tick, choice, target, and resolved or rejected outcome for watched people with a bounded history.
4. **Give simulation systems explicit write ownership.** Source files already separate life, banking, urban development and relationships, but many extend the same mutable World. Today correct behavior depends on the order of calls in `World::step`. Preserve that order during extraction. Name phases and test their visibility rules, including which tick sees a vacancy after a death. Give money transfers, building occupancy and social links one owner each. Translate completed actions into a few typed records where another system needs to react. Keep high-volume local updates direct.
5. **Move scenario geography into Rust-owned world data.** Forest placement uses settlement indices and a fixed hill circle. The renderer independently draws that hill from literal coordinates. Define terrain shapes, settlement seed sites, habitat preferences and placement exclusions once. Generate a seeded map from those inputs and send its geometry to Godot. Persist the generated world or its generation version so changing a scenario cannot move the hill in a player's old save. Keep economic specializations inferred from completed trade.
6. **Separate wire, save and runtime representations incrementally.** The compact position record shares an action byte with two flags. Godot masks to six bits, giving the format an action ID ceiling of 63. Document and test that limit before assigning new IDs. Whole-world saves already have explicit migrations, but the schema-12 reader imports current nested types such as Agents and Market. Freeze serialized layouts where they change and load real old fixtures after changes. Establish separate ownership for protocol and save version changes.

## Parallel work assignment

| Owner | Can change independently | Contract with others | Acceptance example |
|---|---|---|---|
| Simulation logic | Domain rules, feasible choices, reservations, action outcomes, brain scenarios | Typed commands and completed outcomes with stable entity IDs | Two buyers contest the last item. Exactly one sale settles and accounts balance. |
| Interface | Inspector panels, navigation, labels, selection, keyboard and mouse interaction | Named snapshot fields, selection and focus signals | Open a person, follow a relationship and return to the map using a recorded snapshot. |
| Visuals | Sprites, animation, map layers, batching, camera presentation and fidelity | World coordinates, entity IDs, poses and authoritative site footprints | The same building can be picked at all zoom levels and population animation stays within a measured frame budget. |
| World building | Scenario definitions, terrain, habitats, deposits, settlement site rules and seeds | Versioned map data, deterministic generation and placement queries | A second seed layout moves the hill, draws it correctly, keeps farms off stone and produces distinct observed sales profiles. |

One integration owner per change coordinates shared IDs, tick ordering, save migrations and protocol changes. This can rotate. Agree on a small real example and fixture before concurrent work. UI and visual agents can use the fixture while the simulation and world agents implement their sides. A single composition file can wire modules together. Give each worker separate panels, layers or domain files instead of all editing that file.

## Suggested first deliveries

1. Establish the baseline and safe test runner. Record a representative populated-town save and matching viewer frame in a small fixture set, using synthetic worlds. Record seed, build and rules version with each measurement.
2. Extract the viewer connection and snapshot decoder from main.gd behind the existing wire format. Extract one person inspector and one terrain layer. Re-run the existing headless viewer check against the same frame. This opens two independent Godot work areas.
3. Split fast movement updates from slow reports. Compare paused, moving, zooming and wealth-panel-open workloads on the same world. Add decision saturation counters and selected-person decision records alongside the change.
4. Deliver a second geography through the map contract. Test a changed hill and settlement order. Run seeded small-population scenarios for survival, jobs completed, trade, births and settlement progression. A balanced ledger alone cannot tell whether a village is livable.
5. Profile a mature economy at 10k and 100k, then attempt one million. Measure tick p95/p99 against the 100 ms tick interval, viewer frame time, bytes per second, decision age, memory, save/load peak and replay equality. Include growing family and relationship networks. Let the slowest measured subsystem determine whether to add spatial indexes, regional simulation or cheaper distant-world scheduling. If scheduling changes, check distributions of wages, mortality and trade against the detailed model.

The previously published 1.2-million-person run covered ten simulated seconds with an earlier feature set. In this review a fresh-world headless run of the existing release binary with 10,000 people, seed 42, eight workers and 100 ticks reported 6.51 ms p95 and 7.70 ms p99 with balanced accounts. It measures a short step workload and excludes live snapshot and drawing costs. The native workspace's 116 tests and the three browser prototype suites passed during review.
